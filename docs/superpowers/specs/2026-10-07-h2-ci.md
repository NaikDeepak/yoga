# H2 — CI on every pull request

Part of `docs/superpowers/plans/2026-10-07-hardening.md`.

## Goal
Every PR to `main` (and every push to `main`) runs typecheck, the full test suite with the coverage gate, and a production-mode build.
A red check means "do not merge".

## Deliver
1. `.github/workflows/ci.yml`:
   - triggers: `pull_request` to main, `push` to main; `concurrency` cancels older runs of the same ref.
   - ubuntu-latest, Node 22 (`actions/setup-node` with npm cache), `npm ci`.
   - steps: `npm run typecheck` → `npm run coverage` → `npm run build` with `LOCAL_MOCK=false`.
   - The build must not need real secrets. Use obviously fake placeholder values set in the workflow `env:` (e.g. `postgresql://ci:ci@localhost:5432/ci`, `https://example.supabase.co`, `ci-placeholder`). Find the minimum set by running the build locally with an empty env (`env -i PATH=$PATH HOME=$HOME LOCAL_MOCK=false npm run build`) and adding only what it demands. Never copy values from `.env`.
   - `permissions: contents: read`. Pin actions to major versions (`@v4`).
   - timeout-minutes: 20.
2. If the build needs a code change to build without secrets (e.g. a module that throws at import time when a var is missing), stop and hand off to claude with the details instead of changing src/.
3. `docs/environments.md`: a short "CI" section — what runs, where placeholder env lives, that it never has real secrets.
4. `docs/architecture.md`: one line in the relevant ops/tooling place pointing at the workflow.

## Out of scope
Branch protection (Deepak sets it in GitHub), deploys, secrets, e2e tests (H5), changing tests.

## Done when
- Locally: the exact commands from the workflow pass (typecheck, coverage, the build with only the placeholder env).
- `actionlint` if available, else a careful YAML read.
- Commit on branch `ci/pr-checks`, no push. Handoff to claude with the placeholder var list and timings.
